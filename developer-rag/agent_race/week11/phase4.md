# Phase 4 — Extract the Full Trace and Cost Accounting

**Status: COMPLETED**

## Objective

Produce `trace.json`: a complete, machine-readable, schema-matching record of the found
incident, with per-span latency, tokens, cost, prompt version, and context IDs.

## Starting state

Phase 3 located the incident (`medium_01`-shaped `incomplete_grounding`). Phase 2 had just
added the timestamp/cost/result_full instrumentation to `agent.py` needed to populate a real
trace from a real execution.

## Files created

- `week11/extract_trace.py` — runs the REAL `agent.py` (via Phase 0's fakes) with the
  incident's exact pre-fix conditions explicitly requested (`mitigated=False,
  parallel_hint=False, compact_history=False`), then builds `trace.json` from the real
  returned log.
- `week11/trace.json` — the deliverable itself, generated by running the script above.

## Why `mitigated=False` is passed EXPLICITLY here, after Phase 5's fix changed the default

This script intentionally asks for the OLD behavior by name, not by relying on whatever
`agent.py`'s current default happens to be — because the point of this script is to keep the
incident **reproducible on demand** after the fix ships, for future debugging/training
purposes, not to test which behavior is currently default (that is `test_regression_w11.py`'s
job, in Phase 5, which deliberately does NOT pass these flags).

## Reconciliation

`total_tokens` in `trace.json` (2693) = sum of the two `llm_call` spans' `input_tokens +
output_tokens` (703+126 + 1751+113 = 2693) exactly — no double counting between the trace
total and its spans, since there is exactly one level of span nesting (no nested sub-agent
calls in this track's single-agent path).
